# Simplify agent instructions around canonical contracts

## Context

The first audit corrected inconsistencies but retained fourteen skills, repeated
routing and workflow instructions, and phase-based session stops. Interpretation
probes did not establish that those instructions were necessary. The human
approved candidate A on 2026-09-05 after reviewing concrete cuts, replacement
text, preservation boundaries and a paired executable repair pilot.

## Decision

Ordinary work follows the current request and affected canonical contracts.
Retain five specialized skills for preview evidence, human PR explanation,
existing PR findings, skill maintenance and database schema work. Retire nine
generic skills and the separate LOOP_ENGINEERING router. The manifest owns
short discovery descriptions; both supported wrapper trees remain generated.
PR remediation retains its conditional provenance, epoch and terminal protocol.

AGENTS is a small entrypoint; AGENT_WORKFLOW owns shared completion, validation,
delegation and failure handling. Domain rules point to canonical owners; other
hosts retrieve those owners directly without an additional Cursor-rule read.
SECURITY remains canonical across all tools. Its secrets, executable trust,
production-database and human-only account-deletion rules are unchanged.

Continue healthy investigation, implementation and repair within the same
approved outcome. Persist progress and real interruption/blocker state using
notes/README templates. A phase transition alone does not require a new session.
Scoped child packets require outcome, edit boundary, proof and constraints,
without a heading quota. Parent owns integration and sensitive work; children
cannot self-accept. Meaningful work receives integrated independent review and
read-only final verification, with extra leaf review conditional on risk.
Bounded repair budgets cannot be reset by another child or note.

Keep the existing document/task checker and task metadata grammar. Its graph
expresses structural dependencies, not user authorization or semantic approval.
Remove dead entries and broad procedural impact seeds; canonical substantive
contract dependencies remain. Generated correctness and secret checks remain.
The existing proportional-validation final gate remains: final code/config or
validation-contract changes require check:readonly; full Expo preparation and
validation remain parent-owned when applicable. Reuse proof for unchanged inputs.
Local completion, acceptance and external delivery states remain separate.

These rules replace the four linked decisions only in their session, routing,
packet-format and infrastructure ownership arrangement. Their canonical security,
portable state, bounded ownership and independent-checking purposes remain.

## Consequences

The library has fewer discovery choices and ordinary work retrieves less generic
procedure. Optional PR detail remains counted as surviving instructions. The
approved design is preserved in the notes dossier; broader paired application
and boundary trials and integrated checks must substantiate implementation.
Static line reductions are not runtime token savings or reliability proof.
Global duplicate removal and preview-driver substitution remain separate scopes.
No new dependency, orchestration runtime, graph traversal or host model change.

## Revisit when

Executed representative work misses a canonical invariant, sensitive retrieval
fails on a supported host, or a retained procedure no longer earns its discovery
cost. Fix the relevant owner/trigger before rebuilding generic scaffolding.
